# Colours learning area — proposed curriculum

## What exists now

The Home card **Colour Sort / Farben sortieren** launches one Compose screen directly. `ColourSort` has two category IDs, `colour.red` and `colour.blue`, and four semantic object IDs: red ball, blue ball, red block and blue block. The screen draws the tokens with Compose Canvas; it has no canonical object-image assets. A child taps a token, then a red/blue category. Replay, Help, immediate correction, bilingual feedback and durable exact-state recovery are already present. The screen does not first teach or explore color names.

`CoreContent.repository()` already contains bilingual records for seven colors (`colour.green`, `.red`, `.yellow`, `.blue`, `.purple`, `.orange`, `.pink`). These are shared vocabulary/weekday cue definitions, not evidence of a seven-color learning activity. Wilma uses the seven day colors as a supplementary semantic cue; color is not the weekday identity. Tell Me scene descriptions also contain color words and contextual color observations, but no standalone color course.

The reusable `learning/sorting/SortingContent` and `Sorting` state machine already serve Colour Sort, Animal Groups and Seasons MATCH. It is suitable when each item has exactly one correct category. `OrderedPlacement` and `SequenceAssembly` provide separate ordered/tap-to-build mechanics. Existing identities are `activity.colours.sort`, revision 1, content 1.1, plus its journal magic/checkpoint and shared progress definitions. Do not silently add tokens/categories to that fixed restore contract.

## Recommended color set and teaching rules

Start with **red / rot, blue / blau, yellow / gelb and green / grün**. Keep red and blue from the current sort, then add yellow and green because they are common early color names, distinct enough for simple picture samples and already present in CoreContent. Four is enough to support matching and small patterns without making the first task a broad color-word test. Do not use color alone to identify an answer outside explicit color learning. Use a visible EN/DE label and a manual Listen action; do not assume the child can read or that sound output is installed.

Use solid, neutral swatches for color-name recognition. Avoid asking “What color is this object?” when the object's rendering/lighting, printed outline or common variant makes more than one answer reasonable. An object task should state the dimension: “Find the red object” or “Which objects are red?” Do not accidentally test object naming or reading when color is the intended concept.

## First implementation recommendation

Start with a reviewable **Explore + Find** slice using the four colors above. It closes the current concept-introduction gap and gives the existing two-color sort a meaningful named-color foundation. Keep the current Home route and its direct launch into Colour Sort during the first delivery; expose Explore/Find only through an explicitly reviewed in-area navigation affordance or a later chooser task. A dedicated chooser becomes justified once at least two additional activities actually work; do not add placeholder cards for future stages.

Before expanding the existing sort’s fixed four-token session, either leave it intact and add a new versioned expanded-sort activity, or implement and test an explicit compatibility decoder that restores the old four placements exactly. New sessions should have new content identities and current format; old sessions should never silently restart or have their categories reinterpreted.

## Artwork backlog

- **Reusable now:** current vector red/blue ball/block tokens (`ColourSortScreen.kt`); seven bilingual color records in `learning/content/CoreContent.kt`; weekday color swatches remain semantic day cues, not color-object content.
- **Missing for the proposed first slice:** no raster artwork; native patches are adequate. Require labeled accessible swatches, a neutral background, consistent patch size, no gradients/textures, and no baked-in bilingual labels.
- **Missing for everyday transfer:** 12 isolated objects (3 per color), language-neutral PNG/WebP with transparent or simple neutral background, aspect ratio approximately 1:1 or 4:3, centered whole subject, one clearly dominant intended color, no embedded words, sufficient separation from other colors, review at phone card scale. Choose familiar school/home objects and record object-to-color facts explicitly.
- **Needs display review:** all Light/Dark and mixing palettes; device brightness/night modes can invalidate tiny shade distinctions.
